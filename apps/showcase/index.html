Reusable PDF ideas.

UPDF is a micro, portable TypeScript PDF engine: immutable declarative data, typed reusable components and native TSX. The synchronous core returns Uint8Array bytes in Node and browsers, without React or a server.

Uppercase TSX names are imported or reusable components such as Document, Flow, Block and Paragraph. Lowercase names such as text and rect are native renderer intrinsics, used deliberately for fixed-position drawing. Core first. Optional means optional.

The entry loads core, not React, Fontkit, Node APIs or SVG. Native VDOM, measured TSX templates and layout demos load on demand, as do the SVG adapter and geometry. Native paths need no geometry adapter.

Fonts can use prepared resources through @updf/core/fonts; the optional @updf/fontkit adapter prepares trusted static TrueType bytes. The initial entry remains parser-free; opting into the freight invoice loads Fontkit and two licensed Liberation Sans font assets (regular and bold).

  • Core uses fixed point geometry and explicit pages. Optional layout supports measured blocks, padding/border/gap and error/hidden overflow, repeated regions and explicit-width atomic table rows, not general CSS layout or row/column spans.
  • Built-in Helvetica: printable ASCII and LF. No shaping, bidi, raster images or full SVG.
  • Prepared fonts support a documented simple LTR Latin/Cyrillic profile, not general typography.
  • Runtime validation and current resource caps still apply. Trusted components are not a sandbox.

This is the unreleased native checkout, not legacy 0.4.15 and not a claim that roadmap features are delivered. Legacy remains separate; a fixed CMR reference is not operational freight paperwork.
